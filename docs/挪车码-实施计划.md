# 挪车码（扫码联系车主）实施计划

> 技术底座：阿里云 ESA「函数和 Pages」+「边缘 KV 存储」
> 形态：移动端扫码页 + 密码保护的网页后台 + 圆形二维码生成/打印
> 状态：**MVP 已实现，本地 96 项自动化测试全过，待部署上线**

---

## 1. 目标与范围

### 1.1 核心目标

- 车主把自己的二维码贴在挡风玻璃上，他人扫码即可打开挪车页面。
- 页面展示该车主名下的车辆，选中车辆后点「一键呼叫车主」直接调起系统拨号。
- 后台可增删改车辆、联系电话、页面文案，并生成/下载/打印圆形二维码。

### 1.2 范围内（MVP）

| 模块 | 内容 |
|---|---|
| 扫码页 | 车辆选择、一键拨号、多车/单车自适应、失效提示 |
| 后台 | 密码登录、车辆 CRUD、排序、启用/停用、页面文案设置 |
| 二维码 | 圆形二维码 SVG/PNG 生成、A6 打印卡片 |
| 接口 | REST 风格 JSON API，全部跑在边缘函数里 |
| 存储 | 单个 KV 命名空间，按「页面文档」聚合存储 |

### 1.3 暂不做（可后续加）

- 多车主自助注册（SaaS 多租户）—— 已确认：单管理员
- 扫码/呼叫数据统计报表 —— 已确认：不需要
- 短信/微信通知车主
- 隐私号（AXB）中转呼叫 —— 已确认：不需要
- 小程序版本

### 1.4 已锁定决策

| 事项 | 决定 |
|---|---|
| 域名 | 已备案，可直接接入中国内地加速 |
| 管理模式 | 单管理员，统一管理全部车辆 |
| 二维码粒度 | 一页一码为主，支持按车辆生成一车一码 |
| 隐私号 | 不使用，返回真实号码 |
| 车牌展示 | 完整展示 |
| 统计报表 | 不做 |

## 2. 平台约束（这些直接决定架构）

| 约束项 | 数值 | 对设计的影响 |
|---|---|---|
| 函数 CPU 时间片 | 5 / 50 / 100 ms 三档 | 选 50 ms；只做路由 + 1~2 次 KV 读写，不做图像处理 |
| 函数响应时间 | ≤ 120 s，网关 10 s 内无响应即 504 | 所有接口保持单次 KV 访问，P99 远低于 1 s |
| 代码包 | ≤ 4 MB | 前端 HTML/CSS/JS 内联打包进函数完全够用 |
| 单次执行子请求 | 4 个 | **禁止**「先查索引再逐车查询」的 N+1 读法，必须一次读整份文档 |
| 开发语言 | 仅 JavaScript (ES6) | 前后端同语言，构建脚本用 Node |
| KV value | ≤ 1.8 MB，控制台手工添加限 100 KB | 整站文档（含全部车辆）远小于 100 KB |
| KV key | ≤ 512 B，**仅允许字母、数字、`-`、`_`** | key 用 `site` / `rl_xxx`，绝不能用 `/` 或 `:` 分隔 |
| KV 容量 | 单空间 1 GB / 账号 10 GB | 单文档几 KB，容量不是瓶颈 |
| KV 一致性 | 最终一致，通常几秒，最迟 300 s | 后台保存后提示「全球生效约 5 秒~5 分钟」 |
| 边缘函数读写 KV | 仅限同阿里云账号 | 单账号部署即可 |
| 免费版请求量 | 10 万次/天，超限返回 503 | 挪车场景请求量极低，长期零成本 |
| 域名 | 加速区域含中国内地必须 ICP 备案 | 已确认已备案 |

> 关键结论：**整站 = 一个 KV key = 一个 JSON 文档**。读 1 次 KV、写 2 次（读 rev + 写），天然满足 4 个子请求限制，也避开 KV 没有事务的问题。

## 3. 架构

```
                    ┌──────────────────────────────┐
  他人扫码  ───────▶ │  移动端页面 /p/{siteId}       │
                    │  车辆列表 → 一键呼叫           │
                    └──────────────┬───────────────┘
                                   │ POST /api/p/{id}/contact
                                   ▼
  ┌───────────────────────────────────────────────────────────┐
  │            阿里云 ESA 边缘函数（单函数，多路由）             │
  │  /p/{id}         服务端渲染移动端 HTML（不含手机号）         │
  │  /admin          登录 / 后台（同一 HTML 外壳，服务端判态）    │
  │  /api/*          JSON API + 会话校验 + 限流                  │
  │  /p/{id}/qr.svg  SVG 生成（服务端兜底）                      │
  └───────────────┬───────────────────────────┬───────────────┘
                  │ EdgeKV get/put             │ 域名绑定
                  ▼                            ▼
        ┌────────────────────┐        move.example.com (CNAME)
        │ KV 命名空间 movecar │
        │ site               │
        │ auth_admin / rl_*  │
        └────────────────────┘
```

无源站、无数据库、无服务器。全部 CSS/JS 在构建期内联进函数，前后台共用同一份产物。

## 4. 页面与交互流程

### 4.1 扫码页 `/p/{pageId}`

```
[顶部]  挪车提示：车主临时停车，如需挪车请联系 {{title}}
        ↓
[车辆卡片 1]  粤B·8**27   白色 · 特斯拉 Model 3   ● 已选
[车辆卡片 2]  粤B·6**12   黑色 · 理想 L7
        ↓（单选，默认选中第一辆）
[ 🟢 一键呼叫车主 ]   ← 大按钮，拇指热区
        ↓
[确认弹层] 即将拨打 138****0000（脱敏）  [取消] [呼叫]
        ↓
   系统拨号盘 (tel:)
```

- 只有 1 辆可用车时**跳过选择**，直接展示呼叫按钮。
- 车辆全部停用或页面不存在 → 友好兜底页（「该挪车码已失效」），不泄露任何信息。
- 车牌完整展示（已确认），可作为对方核对依据。
- 号码只展示脱敏形式（`138****8000`），完整号码仅在 `tel:` 拨号时使用。

### 4.2 后台 `/admin`

```
登录（密码）
  └─ 车辆管理：列表 / 新增 / 编辑 / 启用停用 / 删除
  └─ 二维码：圆形码预览 / SVG 下载 / PNG 下载 / 复制链接 / 打印车贴
  └─ 页面设置：标题、提示语、重置公开 ID
  └─ 账号安全：修改密码
```

交互要点：

- 车辆编辑用弹层表单，保存即写整站文档（含 `rev` 版本号做乐观锁，防止两个标签页互相覆盖）。
- 保存成功 Toast：「已保存，全球节点约 5 秒~5 分钟后全部生效」。
- 重置公开 ID 后旧码立刻失效，需重新下载打印。

### 4.3 一车一码（已启用）

后台「二维码」标签顶部新增「二维码指向」下拉：

- 选「整页一码」→ 沿用原来的 `/p/{pageId}`，展示全部在用车辆。
- 选某辆车 → 生成 `/p/{pageId}?car={carId}`，扫码后只展示这一辆车并直接给出呼叫按钮。

实现要点：

- 扫码页读取 `?car=`：命中在用车辆则按单车结构渲染；车辆已删除/停用或参数非法时回落为整页列表，不让扫码人看到失效页。
- 预览、SVG/PNG/JPG 下载、复制链接、打印车贴全部跟随当前选择；下载文件名带车牌，打印车贴额外印出车牌便于核对。
- `GET /p/{pageId}/qr.svg?car={carId}` 服务端兜底同样支持按车生成。
- 车辆 ID 稳定不变，编辑车牌或号码不需要重新打印；删除车辆则该码自动回落整页。

## 5. 数据模型（KV）

### 5.1 Key 设计

单管理员 + 单页面的场景，**整站数据只用一个 key**：

| Key | 结构 | 说明 |
|---|---|---|
| `site` | 站点文档 JSON | 公开 ID + 文案 + 全部车辆，一次读、一次写 |
| `auth_admin` | `{alg,iter,salt,hash,ver}` | 管理员密码摘要（PBKDF2），`ver` 用于作废旧会话 |
| `rl_{bucket}_{ip}_{slot}` | `{n,blockedUntil}` | 限流计数（近似） |

这样设计的原因：ESA 函数**单次执行最多 4 个子请求**，KV 又没有「按前缀列 key」的能力。分表存储会立刻撞上 N+1 读问题，而单 key 整存整取天然只有 1 次读。容量也完全够——几十辆车不足 10 KB，远低于 1.8 MB 上限。

> Key 命名受 EdgeKV 限制：只能字母、数字、`-`、`_`，所以用 `site` 而不是 `page/main`。

`siteId` 生成规则：8 位 `[a-z0-9]`（去掉易混的 0/o/1/l/i），不可枚举；重置即换新 ID，旧码立刻失效。

### 5.2 站点文档

```json
{
  "id": "g4ybhszv",
  "title": "临时停车，需挪车请联系我",
  "notice": "扫码后可一键呼叫，感谢配合",
  "rev": 3,
  "updatedAt": 1761523200000,
  "cars": [
    {
      "id": "c1",
      "plate": "粤B12345",
      "model": "特斯拉 Model 3",
      "color": "白色",
      "phone": "13800138000",
      "enabled": true,
      "sort": 1
    }
  ]
}
```

- `rev` 用于乐观锁：写入时比对读到的版本，不一致返回 409，防止多标签页互相覆盖。
- `enabled: false` 的车辆不出现在扫码页，取号接口也会拒绝。
- 单文档体积：20 辆车 ≈ 6 KB。

## 6. API 设计

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/p/{siteId}` | 公开 | 扫码页 HTML（30 s 边缘缓存） |
| POST | `/api/p/{siteId}/contact` | 公开 + 限流 | body `{carId}`，返回 `{phone, plate}`（`no-store`） |
| GET | `/p/{siteId}/qr.svg` | 公开 | 二维码 SVG（缓存 1 天） |
| GET | `/admin` | 公开 | 未初始化→初始化表单；未登录→登录表单；已登录→后台 |
| POST | `/api/admin/init` | 公开 + 限流 | 首次设置密码（仅一次） |
| POST | `/api/admin/login` | 公开 + 限流 | `{password}` → Set-Cookie 会话 |
| POST | `/api/admin/logout` | 公开 | 清除 Cookie |
| GET | `/api/admin/session` | 需会话 | 返回站点数据与页面地址 |
| PUT | `/api/admin/page` | 需会话 | 更新标题/提示语（带 `rev`） |
| POST | `/api/admin/page/reset-id` | 需会话 | 重置公开 ID，旧码作废 |
| POST | `/api/admin/car` | 需会话 | 新增或更新车辆（带 `rev`） |
| DELETE | `/api/admin/car?id=&rev=` | 需会话 | 删除车辆 |
| POST | `/api/admin/password` | 需会话 | 修改密码，旧会话全部失效 |

统一响应：`{ok:true,data}` / `{ok:false,code,message}`；错误码 `UNAUTHORIZED / NOT_FOUND / RATE_LIMITED / REV_CONFLICT / INVALID_INPUT`。

## 7. 认证与安全

### 7.1 登录

- 密码用 `crypto.subtle` 的 PBKDF2-SHA256（12 万次迭代 + 随机盐）摘要存 KV，**不存明文**。
- 登录成功签发无状态会话：`sid = base64url(payload) + "." + HMAC-SHA256(payload, ADMIN_SECRET)`，`payload = {exp, ver, n}`。
- Cookie：`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=7d`。
- `ADMIN_SECRET` 通过 ESA **函数变量**注入（勾选加密存储），不写进代码与 KV。
- 改密码时递增 `ver`，所有旧会话立即失效。
- 登录限流：`IP + 10 分钟桶`，5 次后锁 10 分钟（KV 近似计数，允许少量误差）。
- 首次部署引导：`auth_admin` 不存在时，`/admin` 显示「初始化管理员密码」页，仅允许设置一次。

### 7.2 手机号保护

- 扫码页 HTML **不含完整手机号**，点「呼叫」时才请求 `/api/p/{id}/contact`。
- 该接口限流：同一 IP 每小时 10 次；返回 `Cache-Control: no-store`。
- 后台车辆列表里号码默认脱敏显示（`138****8000`）。
- 已知取舍：号码在 KV 中是明文（`phone` 字段），且取号接口会把完整号码返回给调用方。这是「不需要隐私号」决策下的必然结果，防的是批量爬取而非单次查看。

### 7.3 其他

- 写接口校验 `Origin` 同源，配合 `SameSite=Lax` 防 CSRF。
- 所有错误响应不打印手机号与会话值。
- 页面禁收录：`X-Robots-Tag: noindex, nofollow`，并提供 `/robots.txt` 屏蔽。
- 全站 CSP：`default-src 'self'`，禁止外域脚本与 iframe 嵌套。
- 防伪码提示：页面底部标注「本码由车主本人贴置」，减少假码诈骗风险。

## 8. 圆形二维码方案

### 8.1 生成方式

| 层 | 做法 |
|---|---|
| 编码 | 用 `qrcode-generator` 拿 0/1 矩阵，**纠错等级 H（30%）** |
| 绘制 | 自研 SVG 渲染：数据模块画成圆点（半径 48%），三个定位图形画成三层圆角方块（深-白-深） |
| 底板 | 正方形矩阵外套圆形白底（半径 60），矩阵边长 72，四周余量即静区 |
| 静区 | 圆形底板边缘到矩阵 ≥ 6 个模块，任何装饰不侵入 |
| 中心 | 默认不放 Logo；如需放，限制在 20% 面积内并用白底圆环隔离（H 级纠错可容错） |

### 8.2 输出

- `SVG`：矢量，打印用，可无损放大（1024px）。
- `PNG` 1024：贴纸、微信发送（前端 SVG → canvas 转换）。
- `打印车贴`：A6 尺寸，二维码 + 车牌号 + 两句提示语，`window.print()` 直接出纸。
- `qr.svg` 接口：服务端兜底，即使后台脚本异常也能拿到码。

### 8.3 可扫性红线

- **只有底板是圆的，二维码矩阵保持正方形**，否则圆形裁切会切掉定位角，扫码率骤降。
- 打印直径 ≥ 3 cm，纯白底 + 近黑（`#111`）模块，禁止渐变、描边、低对比配色。
- 验收必须在 iOS 相机、微信扫一扫、支付宝扫一扫三端各测一次，距离 10~40 cm。
- 已将渲染矩阵与 `qrcode-generator` 原始矩阵逐格比对，603 个数据点 0 误差。

## 9. 技术选型与目录结构

### 9.1 选型

- 前端：原生 JavaScript（无框架），移动端优先，CSS 变量 + 单文件样式。
- 构建：`esbuild` 把 CSS / JS 内联进函数，产出单个 `dist/index.js`（约 150 KB，远低于 4 MB）。
- 存储：EdgeKV 内置 API（`new EdgeKV({ namespace })`），整站数据放一个 key。
- 二维码：`qrcode-generator` 出矩阵 + 自研圆点 SVG 渲染器，前后端共用同一份 `shared/qr.js`。
- 本地调试：Node 内置 `Request`/`Response` 直接跑同一份构建产物，只需 mock `EdgeKV`。

## 11. 部署步骤（运维手册）

1. 登录 ESA 控制台，确认站点已接入、CNAME 已生效。
2. **边缘计算和 AI → KV 存储**，创建命名空间 `movecar`（记下名称，函数变量要用）。
3. **函数和 Pages → 创建函数**，规格选 50 ms，语言 JavaScript。
4. 在函数详情页添加函数变量（生产环境）：
   - `KV_NAMESPACE` = `movecar`
   - `ADMIN_SECRET` = 32 字节以上随机串，勾选**加密存储**
5. 执行 `npm run build`，把 `dist/index.js` 全量粘贴到函数代码编辑器，保存。
6. 先**发布到测试环境**，用控制台给出的测试 IP 配置 Host 后验证 `/admin`、加车、扫码页。
7. 函数详情页 → 域名，绑定你的域名（如 `move.yourdomain.com`），按提示添加 CNAME。
8. 访问 `https://move.yourdomain.com/admin`，设置管理员密码并录入车辆。
9. 进入「二维码」标签，先手机扫码验证，再下载 SVG/PNG 或直接打印车贴。
10. **发布到生产环境**。之后每次改代码：粘贴新代码 → 生成版本 → 灰度或全量发布。

> 注意：函数变量在修改后需要**重新生成版本并发布**才生效，改完变量别忘记发布。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 域名未备案 | 无法在中国内地加速，扫码打不开 | 先备案，或用已备案域名；临时可海外区域但不推荐 |
| 圆形码打印后扫不出 | 核心体验失效 | 矩阵保持方形、H 级纠错、静区 4 模块、三端实测 |
| 手机号被爬/滥用 | 隐私泄露、骚扰 | 点呼才取号 + IP 限流（每小时 10 次） |
| 假二维码贴在别人车上诈骗 | 品牌与安全风险 | 页面标注来源、支持后台随时重置公开 ID 使旧码作废 |
| KV 最终一致 | 改号后短时间内仍打旧号 | 保存提示生效时间；关键场景等待 5 分钟再贴新码 |
| 免费额度 10 万/天 | 极端刷量导致 503 | 限流 + 页面 30 秒边缘缓存，正常场景不可能触顶 |
| 微信内置浏览器 tel 行为差异 | 无法一键拨号 | 用 `location.href='tel:'` 触发，确认弹层已显示脱敏号可长按复制 |
| 管理员密码遗忘 | 无法进入后台 | 删除 KV 中 `auth_admin` 后重新初始化（车辆数据不受影响） |
